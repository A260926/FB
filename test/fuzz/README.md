# Structured open-upvalue fuzzing chain

This directory adds a model-based fuzzer for the most failure-prone part of
Wren's closure implementation: **open upvalues that survive Fiber suspension,
stack relocation, variable mutation and scope exit**. The failure it targets
is subtle — values can still look correct while the *aliasing relationship*
between closures sharing one local has silently broken.

The existing single-shot closure/Fiber tests and the public-API baseline in
`task_support/baseline.sh` are untouched. This is an additional, structured
chain, not a replacement, and it never uses another scripting engine as the
reference: the oracle is an independent C model in `upvalue_model.c`.

## Files

| File | Role |
| --- | --- |
| `upvalue_plan.h` | Shared plan/declaration/observation types and limits |
| `upvalue_plan.c` | Bounded binary plan decoder, encoder and structural validator |
| `upvalue_model.c` | Independent C reference model (own malloc'd cells) and the benign-Wren renderer |
| `upvalue_fuzz.c` | Moving allocator, public-API execution chain, fixed corpus, deterministic generator, `LLVMFuzzerTestOneInput` and a libFuzzer-free `main` |
| `check-upvalues.sh` | Builds plain + ASan/UBSan, runs the chain, then proves two source mutations are detected |
| `example.generated.wren` | A rendered combined plan (regenerated by the check script) |
| `example.standalone.wren` | A hand-written, directly runnable plan instance |

## Pipeline

1. **Decode** a raw byte string into a finite, fully validated `UpPlan`.
2. **Model** the plan in `upvalue_model.c`. Every captured *declaration* is one
   mutable cell shared by all closures naming that declaration. The model keeps
   the Fiber execution position and local environment in its own logical state
   and never reads Wren bytecode, upvalue structs, handles or real return
   values.
3. **Render** the same plan to a benign Wren program and execute it through the
   real embedding chain — `wrenInterpret`, `wrenMakeCallHandle`, `wrenCall`.
4. **Diff** the ordered observation log against the model stream, recording the
   first differing declaration, operation and values.

Identity is modeled by **declaration, not by name**. Same-name shadowing and
same-slot reuse therefore produce distinct cells; multiple closures capturing
one declaration share one cell; capture forwarded through intermediate
functions still reaches the original cell.

## Input wire format

Multi-byte integers are little endian; all values fit in one byte unless noted.

```
magic            1 byte, must be 0xA5
version          1 byte, must be 0x01
deep-call seed   1 byte, normalized to deep depth in [4, 26]
decl count N     1 byte, 1..24
N declaration records
op count M       1 byte, 1..80
M operation records
```

Declaration records:

```
VAR   (kind 1): [1][flags(bit0 = shadow name)][blockDepth 0..5]
                [initial.lo][initial.hi]                 (10-bit value)
FN    (kind 2): [2][fnKind 1=read 2=write][blockDepth 0..5]
                [capturedDecl][indirect 0..2]
                [write.lo][write.hi]                      (10-bit value)
FIBER (kind 3): [3][blockDepth 0..5][yields 0..3]
                [hasWriter 0/1][write.lo][write.hi]
                [locDecl][readerFnDecl][writerFnDecl or 0xFF]
```

Operation records:

```
SCOPE_ENTER/SCOPE_EXIT/GC/DEEPEN : [code]
DECL         [code][decl]
ALIAS        [code][targetVarDecl][sourceFnDecl]
CALL         [code][fnDecl][viaHost 0/1]
FIBER_NEW    [code][fiberDecl]
FIBER_RESUME [code][fiberSlot][viaHost 0/1]
```

### Length and limit rules

* At most 24 declarations, 16 distinct captured cells, 20 closures, 5 block
  nesting levels, 3 live fibers, 80 operations, deep-call depth 26.
* Truncated input, an unknown op/kind, or an over-limit count is rejected with
  an `UpDecodeResult`; it is **never** reported as an interpreter defect.

### Declaration-reference legality (enforced by the decoder)

* Every reference names an already-materialized declaration of the right kind.
* An FN may capture only a live VAR whose block is not deeper than the FN's
  block. A fiber's reader/writer must capture that fiber's own `locDecl`.
* An FN cannot capture a VAR that already holds an aliased closure, and a
  captured cell cannot become an alias target (cells stay integer-typed).
* A shadow-named cell captured by a closure must be the innermost same-named
  local in scope, matching Wren's textual name resolution.
* A Fiber is resumed at most `yields + 1` times and only while in scope.
* Scope enter/exit must be balanced and within the nesting limit.

Rejected inputs return early; the driver's own handles are only consulted after
a successful decode, so a malformed corpus cannot turn a dangling checker
handle into a false interpreter failure.

## Memory and relocation guarantees

`upvalue_fuzz.c` installs a moving allocator through
`WrenConfiguration.reallocateFn`. Every non-zero reallocation is served from a
freshly allocated, distinct address: valid old contents are copied across and
the old block is released (with header magic and trailing canaries checking for
overruns), so correctness cannot depend on `realloc` happening to keep a block.

Under `-DWREN_FUZZ_TESTING`, `wrenEnsureStack` and `wrenCollectGarbage` expose
read-only counters (`wren_fuzz_stack_moves`, `wren_fuzz_open_upvalue_moves`,
`wren_fuzz_gc_count`). They never change interpreter behavior. A generated
deep call makes a Fiber that still holds open upvalues genuinely grow its
Value stack; the run only counts if a relocation happens **while an open
upvalue exists**, and explicit `wrenCollectGarbage` calls plus a small initial
heap threshold force real collections between call boundaries.

Fibers and closures the host must retain are held with `WrenHandle`; after the
script-side references are overwritten they remain valid roots. Borrowed slot
and string pointers are never retained across a later allocation.

## Running

```sh
bash test/fuzz/check-upvalues.sh
```

This builds a plain and an ASan/UBSan binary, runs the fixed corpus plus 300
distinct generated plans (each replayed twice in a fresh VM), and on success
prints:

```
UPVALUE_MODEL_OK
UPVALUE_MOVE_OK
UPVALUE_REPLAY_OK
```

It then copies the sources into a temporary tree and independently (a) deletes
the open-upvalue stack-relocation correction and (b) deletes the same-slot
upvalue reuse check. Both mutated VMs still compile; each is caught by the same
checks as a concrete value/identity deviation (a compile failure is not treated
as a detection).

The no-libFuzzer driver also accepts raw corpus files:

```sh
./upvalue_fuzz file1.bin file2.bin      # replay inputs through the shared entry
./upvalue_fuzz --print-source 0         # print rendered fixed plan 0
```

When built with `-DLLVM_FUZZER` against a libFuzzer runtime, the same
translation unit provides `LLVMFuzzerTestOneInput`; both entry points share the
identical decode/model/execute code.

## Scope

Only the described sub-language is handled. Exceptions, `Fiber.transfer`,
imports and host resources are intentionally excluded.
