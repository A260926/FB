# Floor 0 修复说明

本目录记录 floor 0（LSP 谱包络）修复的起点与验证方式：

- `run.sh`：复现两个起点偏差（Bark 映射位置、LSP 累积），观测输出保存在
  `record.txt`。带 `REQUIRE_CORRECT_FLOOR0=1` 运行时，偏差会被报成失败。
- `check_target.sh`：确认 `floor0_regression_test.go` 中三个新测试真正运行且
  没有跳过，并联跑既有的 TestDecode、TestIMDCT 与起点记录。

修复按 Vorbis I 规范分三个层次，互不掩盖：

## 1. 位流系数恢复（floor0.Decode）

原因：规范要求码书向量按"增量"解释——每读一个向量，把各分量累加到上一条
累积值上，得到同一条累积 LSP 序列；最后一个向量只取剩余阶数个系数。旧代码把
`last` 设成上一个向量的原始末值而不是累积末值，累加链断裂（0.2、0.2、0.2 被
还原成 0.2、0.4、0.4 而不是 0.2、0.4、0.6）。

影响：所有阶数大于码书维度的 floor 0 流，LSP 系数从第二个向量起全部错误，
谱包络形状随之错误。修复不改任何位消耗：最后一个向量仍只读一个码字、只取
剩余系数，不会多消费后面的 residue 位（测试用哨兵位验证）。

## 2. 谱包络曲线（floor0.Apply / mapResult）

原因有三：

- Bark 映射公式少了一对括号：`rate*i/2*n` 算成了 `rate*i*n/2`，而规范是
  `rate*i/(2n)`（当前块的频率坐标）。48 kHz、32 频点、64 格时，第一个非零
  频点被放到 63 格而非 16 格，整条曲线的频率轴全错。
- 奇数阶的 `q = 1 / 4` 是整数除法，实际得 0。奇数阶时 `p+q` 在
  `cos(w)=±1` 处变成 0，曲线在这些频点发散成 +Inf。
- 循环上界 `int(f.order-3)/2` 对 uint8 的一阶会发生下溢（1-3 变成 254），
  循环 128 次并越界读取系数。

影响：任何使用 floor 0 的流，谱包络要么频率位置错乱、要么奇数阶发散、
一阶直接崩溃。修复按规范逐点求值，奇偶阶（含一阶）、零频附近、最后一个
频点、多频点共用同一 Bark 格的情形都由 TestFloor0Curve 覆盖。

## 3. 重叠 PCM（decodePacket 链路）

原因：前两层修复前，正确的 residue 与 IMDCT、窗口重叠只会把错误的谱包络
忠实放大到 PCM。修复后需要证明整条链（setup 声明 → 包内码书向量 → 谱包络
→ 窗口重叠 → PCM）与规范一致。

影响：TestFloor0Packets 用 Go 构造合法 identification/comment/setup 头与
音频包（非零 residue、单声道、两声道不对称系数，短、长、长、短连续块加一个
零 amplitude 包），经 ReadHeader/Decode/DecodeInto 运行；参照 PCM 由自建
LSP 与 residue 算出频谱，再做直接余弦变换与显式窗口重叠。零 amplitude 包
表示该声道没有 floor，输出只剩上一包的重叠部分，不沿用旧曲线。两个入口的
逐样本结果与长度一致，第一包预滚不输出，Clear 后重新预滚，目标缓冲有效区
以外的哨兵不变。
