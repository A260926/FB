# splice --cut-plan：删除表与联合选窗

本目录的脚本验证原有 SoX `splice` 行为，以及新增的 `splice --cut-plan`
联合选窗模式。

```
sh task_support/build.sh     # 编译库与 sox_sample_test
sh task_support/baseline.sh  # 原版双声道 splice 对照
sh task_support/check.sh     # 完整回归：旧对照 + planner/pcm/lifecycle 三组
```

## 删除表

`cuts.txt` 每行两个十进制无符号整数 `a b`，表示原输入帧坐标中的半开删除
区间 `[a,b)`；一帧包含全部声道，所以坐标对所有声道一致。空行和以 `#`
开头的整行注释允许出现，其他多余字段会被拒绝。

约束（任一项不满足即报错，且不会消耗输入）：

- 非空计划最多 64 段；
- 每段 `a < b`；
- 按起点严格递增；
- 原区间互不重叠；
- 所有端点都不超过声明的输入帧数。

## 命令例子

```sh
sox -q -D --buffer 8192 \
    -t raw -e signed-integer -b 32 -r 48000 -c 2 in.s32 \
    -t raw -e signed-integer -b 32 out.s32 \
    splice --cut-plan cuts.txt --overlap 512 --search 32
```

- `--overlap W`：淡入淡出窗宽，`1..1024` 帧。
- `--search S`：每个接缝的整数偏移范围 `[-S,S]`，`0..64`。
- 新模式的参数不能和旧的位置参数或 `-h/-t/-q` 混用。
- 只使用三角线性交叉淡化。输入必须有已知、且能被声道数整除的
  `signal.length`，声道数 `1..8`。

## 精确代价与平局规则

每段 `i` 选一个整数偏移 `d_i ∈ [-S,S]`，两端窗口一起平移：

- 左窗：`[a_i + d_i - W, a_i + d_i)`
- 右窗：`[b_i + d_i, b_i + d_i + W)`

左右窗都必须落在实际输入 `[0,N)` 内；相邻接缝还需要
`b_i + d_i + W <= a_(i+1) + d_(i+1) - W`。等号合法，表示两段淡化窗紧挨。

候选代价是左右窗中同位置、同声道 `sox_sample_t` 差的平方和，所有声道共同
决定一个偏移。差值和累计平方和都用 `__int128` 按数学整数精确计算，不经过
浮点，也不会先混声道再求差。

在全部合法偏移序列中取**总代价之和**最小者；若并列，取整个有符号偏移向量
按字典序最小者。规划是全局联合优化（动态规划 + 回溯），不是逐接缝贪心，
复杂度约为 `O(段数 × (2S+1)²)`，元数据空间 `O(段数 × (2S+1))`。

不存在任何合法偏移序列时，在读取输入之前就报错；不会丢弃某个接缝、缩短
`W` 或自动合并删除区间。

## 渲染与离线存储

- 先原样输出到第一个左窗之前；
- 每个接缝把左右窗按 `(1-j/W)*left + (j/W)*right` 交叉淡化 `W` 帧，
  `W=1` 也按同一公式；取整和饱和沿用 SoX 约定；
- 两段淡化窗之间未参与淡化的保留帧逐样本原样输出；
- 输出长度恰好是 `N - sum(b_i-a_i) - 段数*W`，偏移只改变接缝位置。

这是离线效果：所有输入 PCM 先顺序写入临时文件（`lsx_tmpfile`），规划完成
后再随机读取候选窗口。内存中的 PCM 缓冲只有两个 `W` 帧窗口，合计
`channels*(4W+2S+8192)` 个样本以内，不随输入总长增长；计划、代价与回溯
元数据不计入该上限。音频不重采样、不变调、不插零，也不分声道处理；
计划坐标始终对应原输入，不会因为前面删过声音而顺移。

## 测试内容

- `planner`：与独立枚举的小计划参照对比，覆盖“两个单独最优偏移互不兼容、
  联合最优可行”的短保留岛、静音全平局、需要全局字典序决定的平局、`S=0`、
  无可行路径和接近满幅的整数代价。
- `pcm`：通过真实 SoX CLI 处理带原位置标记的多声道输入，逐样本与独立渲染
  参照对比，包含首尾界限、`W=1`、两个和三个接缝、声道极性相反、各声道偏好
  不同，以及不同缓冲/输出容量下完整 PCM 一致。
- `lifecycle`：64 与 8192 缓冲、不同 drain 容量、完整 drain、取消、临时文件
  清理，以及明显大于内存上限的输入下的实际缓冲容量和磁盘处理。
