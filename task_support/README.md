Run `node task_support/run.js baseline` for the existing CPU Render or `target` for the required new module, test groups and example. Node builtins only. Each group in test/clipmap.js is a synchronous export `(api, check) => actualCheckCount`, where api contains TerrainSource, TerrainClipmap and runViewer. No test registration framework or main is required. Failures, early exits, absent groups and zero assertions fail the parent runner.

`runViewer({width,height,map,camera,background,configure,collide,session})` evaluates local browser scripts in their HTML order. It removes exactly the final `Init();` startup, without changing Render. It creates an in-memory framebuffer, assigns the provided map and camera fields, invokes optional configure(context), optionally calls the production UpdateCamera when collide is true, and invokes the production DrawBackground/Render. The return value contains `{color:Uint32Array,camera,session}`. Pass a previous result.session to reuse the same viewer globals; otherwise a fresh viewer is created. configure exposes the VM's browser-global object: use your new public mode/source lifecycle entry points there to select clipmap mode and share a view. No DOM, image decoding or browser timers are supplied. Keep the browser's trailing Init(); startup and classic local script entry so the same production renderer can be driven headlessly. Tests and examples can `require('../task_support/viewer').runViewer`.

The example receives a new output PPM path as argv[2]; it must create a nonempty P3 or P6 image during this invocation. Its compilation/runtime failure or lack of output fails target. Missing implementation, tests or example is an expected failure of the starting snapshot; do not add empty substitutes.
