# REX2 support boundary

Reference: Intel APX Architecture Specification, 355828-004US (April 2024), section 3.1.2.1.
https://cdrdv2-public.intel.com/819797/355828-intel-apx-spec.pdf
The task scope is a deliberately bounded subset of that published instruction format, not a claim to implement all APX.

REX2 occupies D5 followed by a payload whose bits 7..0 are M0,R4,X4,B4,W,R3,X3,B3 (ordinary, non-inverted bits). M0 selects legacy map 0 or 1; the following byte is the opcode itself, so map 1 does not consume a separate 0F. The three high register bits extend GPR register/base/index identities to five bits. W, operand-size override and address-size override follow the corresponding legacy GPR rules. An 8-bit operand under REX2 uses SPL/BPL/SIL/DIL at encoded IDs 4..7, never AH/CH/DH/BH. R16B..R31B are distinct normal registers; their public metadata must agree with the established GPR8 API's ID convention (which also represents the old high-byte registers). In particular, preserve IDs 0..19 for the old GPR8 values and assign R16B..R31B IDs 20..35 (architectural index plus 4); GPR16/32/64 use architectural IDs 16..31. Do not silently renumber old enum constants or change old GetId/Encode pairs.

Required map-0 opcodes: MOV 88,89,8A,8B and B0..BF; LEA 8D; ADD 00..03; SUB 28..2B; CMP 38..3B. Required map-1 opcodes: CMOVcc 40..4F; SETcc 90..9F (the latter uses a byte r/m destination and its ModRM.reg bits remain opcode-extension/ignored, not a register operand). Follow the old instruction's operand access, flags and width semantics. Memory operands support the ordinary ModRM/SIB forms, displacement sizes, RIP-relative and 67 address-size override in long mode. Do not extend EGPR handling to non-GPR operands.

Usual address sentinel rules still apply: mod=00/rm=5 is relative addressing regardless of B extension; mod=00/SIB.base=5 has no base and consumes disp32, regardless of B extension. SIB.index denotes no index only when its full extended identity is 4; an extended index such as R20 is real. Non-SIB X bits have no address index to extend. Displacements and immediates retain their actual positions in the original bytes. Relative addresses use the entire decoded instruction length, including REX2 and preceding legal legacy prefixes. Reject an immediately preceding REX, REX2 followed by a map-0 prefix byte, invalid legacy operand combinations, truncations and instructions longer than 15 bytes using ordinary failure statuses. Other REX2 opcodes can return any documented failure/unsupported status. Non-long modes continue to treat D5 using the existing AAD path.

Expose instruction.raw.rex2 with fields offset, payload, M0,R4,X4,B4,W,R3,X3,B3, plus an instruction attribute identifying REX2. Failed calls do not provide usable instruction/operand results; a subsequent valid call on the same decoder must remain valid. Preserve the decoder context needed by DecodeOperands without rereading or rewriting the input. No encoder support is requested; extended-register encoder inputs may return unsupported, while existing encoding results remain unchanged.

Fixed image bytes and their ELF container are generated in image.h. The generator supplies input only, not target decoding results. New tests must register prefixes/registers/addressing via task_support/check.h. Use independent expected fields and strings in addition to comparing the two decode APIs. Document any newly public register metadata convention in include/Zydis/Register.h or a companion document.

Read-only address relation: ZydisCalcAbsoluteAddressEx must consume the decoded EGPR operands with a synthetic ZydisRegisterContext. Test 64-bit SIB arithmetic, address-size-override wrapping after the entire sum, and RIP-relative instruction-end addressing against independently listed addresses. The context is supplied data; never read or execute the referenced memory. No separate register-ID convention may be invented for address calculation.
