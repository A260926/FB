# On-disk thread state layouts
This contract uses ordinary non-authenticated register states from Apple's public XNU definitions in `osfmk/mach/i386/{thread_status.h,_structs.h}` and `osfmk/mach/arm/{thread_status.h,_structs.h}` (https://github.com/apple-oss-distributions/xnu). No target code is executed. Read integer fields using the Mach-O stream's endianness, not the host's struct layout. CPU type 7 or 0x01000007 selects x86; 12 selects ARM, 0x0100000c selects ARM64. Unknown CPUs preserve raw records only. Known flavors from another family remain raw.

Each command payload is a sequence of u32 flavor, u32 count, count*4 raw bytes. Record offset includes the 8-byte load command header. Header and payload belong to the record; expose payload separately. A command must be consumed exactly; reject incomplete headers or payloads. Known counts below are exact, and unknown counts (including zero) are preserved if contained. Checked arithmetic is required for spans and segment coordinates; report a descriptive exception on an invalid known record or overflowing range.

* i386, flavor 1, count 16: 16 u32 `eax ebx ecx edx edi esi ebp esp ss eflags eip cs ds es fs gs`.
* x86_64, flavor 4, count 42: 21 u64 `rax rbx rcx rdx rdi rsi rbp rsp r8 r9 r10 r11 r12 r13 r14 r15 rip rflags cs fs gs`.
* x86 unified flavor 7, count 44: u32 inner flavor, u32 inner count, followed by a fixed 168-byte union. Inner flavor 1/count16 or 4/count42 uses the corresponding layout above; any remaining union bytes are padding retained in the outer payload. Unknown inner flavor leaves the entire outer record undecoded, rather than manufacturing a new record. Known inner counts must match.
* ARM, flavor 1, count 17: 17 u32 `r0 ... r12 sp lr pc cpsr`.
* ARM64, flavor 6, count 68: 33 u64 `x0 ... x28 fp lr sp pc`, then u32 `cpsr`, then 4 padding bytes. Expose padding as raw bytes, not a register. Pointer authentication and host opaque-pointer layouts are outside scope.

A decoded state has one architecture identifier, named registers as unsigned 64-bit values, PC, and SP. Do not sign-extend 32-bit registers. The legacy Thread constructor has no CPU argument: it preserves records with no decoded state. The File parser must use a CPU-aware overload or equivalent internal context without changing the old signature.

An entry source's raw coordinate is LC_MAIN's offset or decoded PC. Segment candidates identify the segment's load command index and carry VA and optional file offset. MAIN candidates require `fileoff <= offset < fileoff+filesize` and a displacement also inside vmsize; UNIXTHREAD candidates require `vmaddr <= PC < vmaddr+vmsize` and have file bytes only when the displacement is below filesize. No execution/protection heuristic filters candidates. No symbol lookup, recursive modules or address-space allocation is required. `LC_MAIN` and `LC_UNIXTHREAD` produce sources; `LC_THREAD` does not. Preserve source and candidate command order. File/fat-slice offsets remain relative to that Mach-O image, not the outer fat file.
