# LLVM basic-block address maps: supported contract

Source: https://llvm.org/docs/Extensions.html#sht-llvm-bb-addr-map-section-basic-block-address-map (LLVM 21 encoding). No LLVM library is needed.

Read every section of type 0x6fff4c0a, not just a section with a matching name. ELF64 little-endian EM_X86_64 ET_REL/ET_EXEC/ET_DYN, uncompressed sections only. Support version 2 feature 0/8 and version 3 feature 0/8/32/40. Other versions/features return unsupported with section/offset; PGO analyses are outside this scope.

Entries concatenate without padding. Each starts with version and one-byte feature. Bit 3 means a ULEB128 range count, otherwise one range. Every range has an 8-byte little-endian base address then ULEB128 block count. The first range identifies function entry; subsequent ranges belong to the same function even if their addresses are disjoint. Function identity is (map section index, entry byte offset), not a symbol name. Range identity also has its ordinal.

Every block has ULEB128 ID, gap from previous block end (first gap from range base), then size and metadata. In v3 with bit 5 set, replace size by ULEB128 callsite count, that many ULEB128 deltas, then ULEB128 remaining distance to block end. Callsite deltas run from block begin then from the previous callsite. Final tail starts at the last callsite, or block begin when count is zero. Metadata is ULEB128; preserve its raw value. No machine instruction interpretation or inferred call edges. IDs need not follow address order and are unique within one function, including all ranges. Different functions may reuse IDs. Zero-size blocks are retained as records but never cover an address; zero gap and duplicate callsite offsets are permitted. Callsite end offsets are metadata positions, not return PCs to decrement.

For ET_REL each base field must have exactly one R_X86_64_64 in an SHT_RELA whose sh_info is this map section. Use that RELA's sh_link symbol table. Ordinary defined STT_SECTION/STT_FUNC gives (st_shndx, st_value + signed addend), with checked arithmetic. Ignore the raw base bytes. A section symbol's sh_addr is not a load base. Symbols undefined, ABS, COMMON or extended indices, other relocation types, duplicate/missing base relocations or relocation sites outside base fields are unsupported; do not silently resolve to zero. Table names/order do not matter. Linked objects must have no map relocations; map each base VA to all executable PROGBITS sections containing the complete range. Require one such section and subtract sh_addr; ambiguous/absent mapping has an explicit error. For supported ranges every block/callsite must stay within the selected section; an end at section size is allowed.

The public index owns all records. Each block carries function/range/block identities, code section index, section-relative half-open [begin,end), raw metadata, ordered callsite positions, and map-section byte span. Keep base field's physical file offset and, for ET_REL, relocation table/index and symbol table/index. Map file offsets use section.get_offset(), never VA. The index is all-or-error with a location. On a valid empty file return an empty index. Address queries take (code section index, offset), return every containing nonempty block in physical map/function/range/block order, and cannot cross a gap or borrow an adjacent range. Same numeric offset in two code sections is distinct. Do not mutate, relocate or execute the input.

The example accepts an ELF path, code-section index and decimal offset; outputs one TSV row per hit with all identities, range, callsites and source locations. With no hit prints UNCOVERED. Types/column order are documented by the implementation in doc/bb-map.md. See make_sample.cpp for base input bytes, not a decoder.
