这是新增良性调度入口的公开契约；现有原始字节 OSS-Fuzz 入口保持不变。

`tests/oss-fuzz/session_model.h` 声明 `int coap_model_run(const uint8_t *data, size_t size, FILE *report)`。输入先整份解析；report非空。返回0表示模型一致，1表示首次模型差异，2表示格式/资源/IO错误。0时输出完整报告；1时只输出 `MISMATCH CASE TICK SESSION MID FIELD EXPECTED ACTUAL\n`，FIELD为due/queue/retry/response/nack；2时不写report。report写失败返回2。最多64KiB输入、16个CASE、每CASE4会话、每会话4个SEND、合计256行事件，整数均非负十进制且<=1000000。CASE ID为1..16字节ASCII字母数字下划线，ID不得重复；会话编号0..3，MID为1..65535，token为0..255。

LF文本首行 `COAP_MODEL_PLAN 1`。其后每CASE为 `CASE ID`、1..4行 `SESSION S DEADLINE`、事件行，最后 `END`。所有声明须在本CASE事件前；DEADLINE为1..1000000。事件为 `SEND TICK S MID TOKEN TIMEOUT`、`ACK TICK S MID`、`CANCEL TICK S TOKEN`、`CLOSE TICK S`。TIMEOUT为1..1000，SEND tick小于deadline；每会话MID和token在本CASE内各不重复使用；ACK引用该会话已声明的SEND，tick>=send tick，最多一次；CANCEL token必须引用该会话某SEND，tick>=send tick，最多一次；CLOSE最多一次。事件文本顺序不限，同tick按CLOSE、隐式DEADLINE、CANCEL、ACK、SEND、自动重传顺序；同类按会话、MID或TOKEN升序，自动重传按会话/MID升序。正常终止后的事件是合法SKIP，不产生重复回调。重复/未声明引用、溢出、未知token及不完整文件在创建任何context或worker前拒绝。

一个CASE只用一个真实context，所属会话共享其sendqueue；CASE之间各用独立子进程，父进程核完整回传和退出状态。单worker回传不超过16MiB；父进程必须在等待退出前持续读取所有worker的结果，处理短读与EINTR，不能因管道写满而相互等待。子进程开新context与合法loopback UDP client sessions，不访问外部目标；设置已有packet_loss为100%，不接收socket数据。每条SEND用coap_pdu_init/coap_add_token构造正常CON GET（URI-Path固定regression，不添加原始字节），由coap_new_node/coap_wait_ack_at入队；session的max_retransmit固定2。ACK用相同MID/token的正常ACK 2.05 PDU经coap_dispatch进入真实响应回调；已终态请求的迟到ACK不再分派。CANCEL调用coap_cancel_all_messages按token取消；CLOSE/DEADLINE调用coap_cancel_session_messages，reason固定COAP_NACK_NOT_DELIVERABLE。自动重传pop真实到期node，再调coap_retransmit_at；两次重传后下一次到期产生TOO_MANY_RETRIES。所有PDU/node/session引用按现有所有权契约处理，不伪造状态、回调或网络字节。

在coap_net.c及coap_net_internal.h增加与现有签名相同、末参数为coap_tick_t now的coap_wait_ack_at/coap_retransmit_at；现有函数取真实clock后委托同一核心。仅将这两个核心的调度时间参数化，不全局替换clock。执行器以0为初始逻辑基准，直接按真实队列累计delta算absolute due；不按模型重写node->t，不重建队列掩盖差异，也不使用sleep/coap_io_process。每次队列变更前后维护同一个sendqueue_basetime，所有_at调用传当前tick；同tick多节点到期必须按上述稳定顺序。实现可通过正常pop、remove与相对基准转换推进，不得丢失其他会话的delta。原API兼容。修复取消摘链导致其他节点absolute due变化的问题，涉及head/middle/连续多项及跨会话；不要通过改TIMEOUT或模型期望掩盖。

独立模型按每个SEND记录absolute due=tick+timeout、retry=0和pending状态。重传时retry加1，下一due=当前tick+(timeout<<retry)；retry==2再到期转timeout。ACK转acked，token取消或会话关闭转canceled；终态不再变化。每个事件及自动到期后，逐项核真实队列中的session/MID/token/absolute due/retry、没有额外或缺少节点，并核真实response/nack回调的身份、reason与次数。模型不从真实node复制期望；max_retransmit、回调或队列差异都必须返回1，不能仅检查最终总数。队列清空前正常排到最迟deadline，CLOSE/DEADLINE即使没有pending也关闭会话，正常资源释放继续执行。

状态标识为8个逗号分隔十进制数 `u,p0,p1,p2,a,c,t,z`：本会话声明但未发送的请求数、三个retry阶段pending数、acked/canceled/timeout数，及closed位。各计数总和等于该会话声明的SEND数，closed时pending全0。初态及每个非SKIP操作的前后状态必须在独立模型的合法转换图可达：SEND u->p0；RETRY p0->p1或p1->p2；TIMEOUT p2->t；ACK任一p->a；CANCEL某token的p->c；CLOSE/DEADLINE所有p->c并置z。z=1后不再有边。报告STATE只含实际到达的状态，不声称穷举所有调度；发现不可达的真实状态返回1。

报告首行 `COAP_MODEL_COVERAGE 1`，随后 `STATE STATE_ID`，再 `EDGE FROM OP TO HITS CASE_ID WITNESS_HEX`，最后 `CASE ID sessions=N acked=N canceled=N timeout=N retries=N`，均LF。STATE按8元组数值排序，EDGE按FROM数值元组/OP ASCII/TO数值元组排序，CASE按ID排序。OP为SEND/ACK/CANCEL/CLOSE/DEADLINE/RETRY/TIMEOUT；无状态变化的token取消不产生边。HITS为覆盖该边的CASE数，同CASE循环或多会话重复仅贡献一次。见证为能独立重放的完整单CASE计划（保留COAP_MODEL_PLAN头），按事件行数少、再CASE ID字典序选，编码小写hex；其中SESSION按编号、事件按执行顺序规范化，数字无前导零、字段间单空格、每行LF，故等价文本不能改变见证。重新执行见证必须产生相同边。不可跨case拼接。CASE顺序、事件文本顺序、worker退出顺序及指针/随机MID不能改变报告；不导出地址和真实时钟。失败worker或截断IPC不能归并为成功。

`session_model_target.c`导出LLVMFuzzerTestOneInput并复用coap_model_run：格式错正常忽略，模型差异立即失败；不启动原始字节变异、未知协议数据或外部目标。`session_model_replay.c`接受唯一输入文件参数，调用同一API写stdout并返回其状态。新增文件仅为这四个生产文件，不新增测试、示例、Python或依赖。固定支持入口调用LLVM入口重放随附正常计划，并以编译器真实guard覆盖观测确认进入libcoap；不依赖libFuzzer随机引擎。报告提交由调用方负责，API不操作其他路径。
