# Static CLR method index contract

Reference: ECMA-335 6th edition, Partition II sections 22, 24 and 25: https://www.ecma-international.org/publications-and-standards/standards/ecma-335/ .
Input consists of the caller's parsed PE context backed by bytes. Do not load CLR, resolve assemblies, execute CIL, or interpret body instructions.

Support PE32/PE32+, little-endian metadata root BSJB, one #~ or #- tables stream and #Strings/#Blob/#GUID. All stream bounds are relative to the metadata root; heap references never borrow a sibling stream. Use HeapSizes bits 0/1/2 for string/GUID/blob columns, table row counts for simple indexes, and the maximum participating table row count plus tag bits for coded indexes. Support nonzero rows in tables Module(0), TypeRef(1), TypeDef(2), FieldPtr(3), Field(4), MethodPtr(5), MethodDef(6), ParamPtr(7), Param(8), Assembly(32), AssemblyRef(35), NestedClass(41); a nonempty other table is explicitly unsupported. Skip unneeded rows with their correct schemas, not fixed sizes. TypeDefOrRef uses tables 2/1/27 with two tag bits; ResolutionScope uses 0/26/35/1 with two bits. Absent tables have count zero. Heap indexes may be wide even in small files. No signatures need semantic decoding: copy each method signature's complete Blob payload after its compressed-length prefix; validate prefix and extent. Strings are bounded UTF-8 bytes ending at NUL; preserve their bytes.

#~ has no nonempty Ptr tables. #- uses a nonempty pointer table in preference to its target table; if absent, use the target rows directly. TypeDef.MethodList slices the effective MethodPtr/MethodDef row space with one-based starts and the next physical TypeDef's start (last ends at effective count+1). Resolve each logical item through MethodPtr to its physical MethodDef RID. Independently MethodDef.ParamList is sliced in physical MethodDef row order, using ParamPtr/Param in exactly the same way. Reordering a method via MethodPtr does not reorder that physical method's ParamList endpoints. A nonempty MethodPtr/ParamPtr must be a complete permutation of its target rows; empty lists, repeated adjacent list starts, zero-parameter methods and the count+1 end sentinel are normal. List starts themselves are monotone in their owner's physical table order. Tokens always use physical MethodDef/Param RID, never a logical pointer row.

Each method record has TypeDef token, complete nested owner name (namespace-qualified outer name, '+' for inner names), physical MethodDef token, method name, flags, copied signature bytes, parameters in logical list order with physical Param token/name/flags/Sequence, and original metadata row file spans. Sequence 0 is return metadata; preserve it as a parameter record, not an ordinary argument number. Names are not unique identities. NestedClass links row identities even when table rows are not parent-first; detect duplicate parentage and cycles. No inheritance/name-resolution across AssemblyRef is requested.

RVA=0 methods remain records without bodies. Nonzero bodies support managed IL tiny and fat headers; native/runtime method code types are unsupported. Tiny CodeSize is the upper six header bits and header size is one. Fat header DWORD count determines IL start (at least three), CodeSize is at offset 4, and header/body extents must be validated. Copy MaxStack, local signature token and flags for fat bodies; MoreSects may be present, but those trailing sections are not IL and are not parsed or covered. Preserve IL bytes and each corresponding physical file span. Query is on IL half-open ranges, not the method header or trailing data; give every match as method token plus IL byte offset in physical MethodDef order. Zero CodeSize never matches. Raw-backed bytes may continue across adjacent virtual section ranges with nonadjacent raw offsets. Reject holes, ambiguous overlap, overflow and virtual-only tails; do not use pe_rva2ofs's permissive fallback to manufacture readable bytes. PE headers may contain metadata if wholly within SizeOfHeaders. Section flags do not decide whether valid metadata bytes are present.

New API is lib/libpe/include/libpe/clr_methods.h and lib/libpe/clr_methods.c. Expose pe_clr_methods_build, pe_clr_methods_query and pe_clr_methods_free; choose C types consistent with libpe, including a location-bearing error. The entire index owns its strings, signatures, IL and positions, independent of ctx lifetime. Not-managed input produces an empty successful index; a managed but unsupported/invalid input produces no partial index. Do not alter old parsing behavior.

The example examples/clr_methods.c takes PE path and decimal query RVA. Use task_support/sample_io.h for the dependency-free byte-backed pe_parse entry. Print method/type/parameter identities and source offsets as TSV, followed by all query matches (UNCOVERED if empty); document columns in doc/clr-methods.md. No external .NET tools are needed. make_sample.c produces two legal metadata layouts and two method bodies, including a fat header crossing a virtual section boundary. It contains input construction, not an index implementation.

The support build extracts unchanged pe_parse/pe_can_read/pe_rva2ofs/pe_directory_by_entry/pe_machine_type_name functions from original pe.c at the fixed source commit. Original optional OpenSSL hash/import/unload modules are preserved but not linked. sample_io.h is only a caller-owned byte buffer loader and releases the arrays allocated by pe_parse; it never invokes hash APIs. The normal libpe Makefile's source wildcard includes the new production .c. The offline target explicitly links lib/libpe/clr_*.c, the new tests and example; build failures and zero/empty test groups remain failures.
