# CooperativeFFTConvolver：协作式调度与工作单位说明

`fftconvolver::CooperativeFFTConvolver` 在单条音频线程内完成与
`TwoStageFFTConvolver` 相同的两级 FFT 卷积，但不开后台线程：长尾的
一整批 FFT/乘加/逆变换工作被切成可续传的小步骤，分散到后续的小音频块
（quantum）里执行，且不增加任何额外的声音块延迟。

## 1. 结构

- **短头路径**：响应的前 `2T` 个系数交给既有的 `FFTConvolver`，分区
  尺寸为 `B`。这部分不计入协作调度的工作预算。
- **长尾路径**：`g[m] = ir[2T + m]` 被分成 `P = ceil((irLen-2T)/T)`
  个长度 `T` 的均匀分区，使用长度 `N = 2T` 的复数 FFT，按均匀分区
  overlap-add（与 `FFTConvolver` 同一算法）计算。

## 2. 数据什么时候可用、什么时候必须完成

设输入按 `T` 个样本一批，批 `j` 覆盖绝对样本区间 `[jT, (j+1)T)`。

| 时刻（绝对样本位置） | 事件 |
| --- | --- |
| `(j+1)T` | 批 `j` 的 `T` 个样本全部捕获，作业 `j` 入队 |
| `(j+1)T .. (j+2)T` | 用于完成正变换、P 个分区频域乘加、逆变换和 overlap 的“空档” |
| `(j+2)T` | 该作业对声音的**最早贡献**必须已经准备好 |

也就是说，每收到 `T` 个输入产生一批工作，它对声音最早的贡献在这批输入
起点之后 `2T` 处；中间恰好 `T` 个样本（`Q = T/B` 个 quantum）用来把
整批工作做完。调度器保证在播放到 `(j+2)T` 之前该作业已经完成，因此
不会增加除分区尺寸固有 `2T` 之外的块延迟。启动、环形历史回绕、以及输入
停止后的零样本排尾都遵循同一截止时间。

**quantum 的划定**只取决于从 `init` 起累计的输入样本位置：每累计 `B`
个样本为一个 quantum，编号从 0 开始，与宿主每次 `process()` 的长度无关。
不满 `B` 的碎片不触发额外尾部运算。因此同一段信号按 1、7、`B`、`T+3`
个样本拆开调用，得到完全相同的 quantum 编号、任务节奏和（数值容差内的）
输出。

## 3. 可续传内核

每个作业是一台状态机，阶段依次为

```
load → bitrev(正) → 正向FFT → 分区0乘积写入 → 分区1..P-1乘加
     → 共轭 → bitrev(逆) → 逆向FFT → 缩放/共轭 → overlap-add
```

- FFT 是自写的 radix-2 DIT 复数内核，游标为 `(stage, butterfly)`，
  可以在任意蝶形之后挂起、在下一个 quantum 从同一蝶形继续。
- 位反转置换按索引推进，只对真正发生交换的复数槽记账。
- 逆变换用“共轭 + 正向 FFT + 共轭并除以 N”实现，复用同一内核。
- 所有旋转因子和分区频谱在 `init` 时预计算，运行期间不调用任何
  三角函数。

每个阶段都是带游标的普通索引循环，因此不可能只分摊乘加而把整个大 FFT
留在某次小块调用里——正变换和逆变换本身都在 quantum 之间续传。

## 4. 工作单位怎样覆盖实际内核

记 `F = (N/2) * log2(N)`。每个作业真正执行的循环与记账的对应关系：

| `FFTCONVOLVER_TAIL_WORK` 的 kind | 实际内核循环 | 每作业单位数 |
| --- | --- | --- |
| `butterfly` | 一个 radix-2 复数蝶形 | 正、逆 FFT 各 `F`，共 `2F` |
| `mac` | 一个频点的复数乘积（分区 0，写入）或复数乘加（分区 1..P-1） | `P * N` |
| `move` | 一个复数槽的搬移/清零/缩放，或一个样本的 overlap 相加 | 见下，合计 `≤ 10N` |

`move` 的明细：装载 `2N`；两次位反转各 `≤ 2N`（每交换对 4 个槽）；
逆共轭 `N`；逆变换后缩放+共轭 `2N`；overlap-add 与新 overlap 共
`2T = N`。合计 `≤ 10N`，落在预算公式给出的 `12N` 之内。

每个 quantum 的尾部工作不超过

```
ceil((2F + P*N + 12N) / Q) + 16
```

个单位，`+16` 吸收“某段循环必须整段执行、剩余预算放不下”的原子边界。
上报的数字全部来自真实执行的循环（按实际处理的蝶形/频点/槽数计数），
不是按配置倒推；纯索引运算、短头路径、输入捕获与最终输出的逐样本搬运
不计入此预算。

## 5. 缓冲与实时安全性

- 固定工作区只随响应长度和分区尺寸增长：3 个在途作业槽（每个含一个
  `N` 点复数工作谱和一个 `T` 点输出块）、`P` 个输入频谱环形槽、一个
  `T` 点 overlap、3 个 `T` 点输入快照。不保存整段录音。
- 作业槽按作业编号模 3 复用，回收时上一任作业的整个输出区间已经播放
  完毕；输入快照在对应作业的装载阶段读完后才可能被三个块之后的数据
  覆盖，因此历史、未完成频谱、已完成未播放的块互不覆盖。
- 支持 `input == output`：每个样本在被短头路径就地改写之前，先写入
  对应快照。
- `process()` 期间不分配/释放堆内存、不加锁、不等待；`len == 0`
  （可空指针）不推进样本位置也不产生任务。
