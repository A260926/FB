Usage

There are two ways to use the library:
  • Automatic initialization: Create some div elements on your site, and call a function that automatically initalizes all the viewers. This is the easiest way to use the library, but provides less flexibility.
  • Initialization from code: Needs a bit more typing, but it's more flexible than the previous one.

Automatic initialization

Create some elements anywhere on your page with the class name online-3d-viewer. You can create multiple elements with different parameters.

<div class="online_3d_viewer"
    style="width: 800px; height: 600px;"
    model="model.obj, model.mtl">
</div>

You can specify several attributes:

  • model: Relative path to model files separated by comma.
  • camera: Camera parameters (eye, center, up). 9 comma separated number values.
  • defaultcolor: Default color for surfaces with no material. 3 comma separated number values for r, g, b.
  • backgroundcolor: Canvas background color. 3 comma separated number values for r, g, b or four comma separated number values for r, g, b, a.
  • edgesettings: Edge display settings. 5 comma separated values for 'on'/'off', r, g, b, threshold angle.
  • environmentmap: Comma separated list of six images forming a texture box.
  • environmentmapbg: Boolean ("true" or "false") to set the environment map as background.

After placing the elements, call the {@link Init3DViewerElements} function to initalize all the viewers. It must be called after the document is loaded.

window.addEventListener ('load', () => {
    // init all viewers on the page
    OV.Init3DViewerElements ();
});

Initialization from code

You can also initalize the engine from code. In this case you can provide all the parameters as a JavaScript object. See the {@link EmbeddedViewer} documentation for more details.

window.addEventListener ('load', () => {
    // get the parent element of the viewer
    let parentDiv = document.getElementById ('viewer');

    // initialize the viewer with the parent element and some parameters
    let viewer = new OV.EmbeddedViewer (parentDiv, {
        camera : new OV.Camera (
            new OV.Coord3D (-1.5, 2.0, 3.0),
            new OV.Coord3D (0.0, 0.0, 0.0),
            new OV.Coord3D (0.0, 1.0, 0.0),
            45.0
        ),
        backgroundColor : new OV.RGBAColor (255, 255, 255, 255),
        defaultColor : new OV.RGBColor (200, 200, 200),
        edgeSettings : new OV.EdgeSettings (false, new OV.RGBColor (0, 0, 0), 1),
        environmentSettings : new OV.EnvironmentSettings (
            [
                'assets/envmaps/fishermans_bastion/posx.jpg',
                'assets/envmaps/fishermans_bastion/negx.jpg',
                'assets/envmaps/fishermans_bastion/posy.jpg',
                'assets/envmaps/fishermans_bastion/negy.jpg',
                'assets/envmaps/fishermans_bastion/posz.jpg',
                'assets/envmaps/fishermans_bastion/negz.jpg'
            ],
            false
        )
    });

    // load a model providing model urls
    viewer.LoadModelFromUrlList ([
        'model.obj',
        'model.mtl'
    ]);
});

Solid sectioning

The engine can cut a closed solid triangle mesh with a plane and close the cut with cap faces, so the result is again a closed solid. This is real geometry processing, not camera clipping or Three.js material clipping planes: the triangle mesh is actually split, interpolated corners keep their attributes, and the new cap faces belong to the solid. The half of the solid where normal · p + constant ≤ 0 is kept.

The core entry point is the {@link ClipMeshByPlane} function. The plane normal doesn't need to be a unit vector, it is normalized together with the constant. The plane object also carries the material index of the generated cap faces. Cap faces use the unit plane normal, the cap material and no texture coordinates or vertex colors.

// keeps the part of the solid with z ≤ 5, capped with material 1
let sectionedMesh = OV.ClipMeshByPlane (mesh, {
    normal : new OV.Coord3D (0.0, 0.0, 1.0),
    constant : -5.0,
    capMaterialIndex : 1
});

Supported inputs are closed triangle meshes with finite coordinates, outward face orientation and no line elements. Disjoint shells, concave sections, internal cavities and solid islands inside cavities are handled: holes stay open, islands stay capped, and separate instances never share cap loops. Self-intersecting, non-manifold or mutually tangent shells are not required to work. The original mesh is never modified and the returned mesh is independent.

The same section can be applied through the two model level entry points. The plane is always expressed in model world coordinates, so every mesh instance is cut after considering its full parent-child node transformation; shared source meshes are not modified. The cap material index must be a valid index of the model material list, and instance or export transformations must be finite, invertible affine transformations with a positive determinant.

// display: the final BufferGeometry contains side and cap faces, so the
// bounding box and Three.Raycaster see the sectioned solid, including caps
let params = new OV.ModelToThreeConversionParams ();
params.sectionPlane = {
    normal : new OV.Coord3D (0.0, 0.0, 1.0),
    constant : -5.0,
    capMaterialIndex : 1
};
OV.ConvertModelToThreeObject (model, params, output, callbacks);

// export: visible instances are sectioned first, the export transformation
// is applied afterwards
let settings = new OV.ExporterSettings ({
    sectionPlane : {
        normal : new OV.Coord3D (0.0, 0.0, 1.0),
        constant : -5.0,
        capMaterialIndex : 1
    },
    isMeshVisible : (meshInstanceId) => true,
    transformation : new OV.Transformation (new OV.Matrix ().CreateTranslation (10.0, 0.0, 0.0))
});
let exporterModel = new OV.ExporterModel (model, settings);

The export order is: filter mesh instances with isMeshVisible using their original {@link MeshInstanceId}, cut each visible instance in model world coordinates, then apply settings.transformation. Counts, mesh enumeration and index offsets of the exporter model all refer to the sectioned output. With sectioning enabled instances may be expanded into independent output meshes; with sectionPlane set to null the original hierarchy and shared mesh behavior is preserved, and repeated conversions never reuse a previous clipping result.
