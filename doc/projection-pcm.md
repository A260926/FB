# Projection 解混矩阵的 PCM 回归说明

本文档说明 `tests/test_projection_pcm.c` 与
`verification/check_projection_pcm.sh` 的设计：矩阵布局、独立参照、
舍入规则，以及 PLC 与 reset 的时序。测试只使用公开 API
（`opus_multistream.h`、`opus_projection.h`），不改动生产编解码器与
矩阵算法。

## 测试拓扑

```
4 声道确定性信号 ──► 公开 multistream encoder（2 个 coupled stream，
                     48 kHz，每包 960 帧，共 14 包，编码器全程复用）
                          │  压缩包
          ┌───────────────┴────────────────┐
          ▼                                ▼
 projection decoder                multistream decoder
 （测试自备 4×4 解混矩阵）          （恒等通道映射，保留 4 个压缩域声道）
          │                                │
          └────────► 逐样本对比 ◄──────────┘
                （参照 = 测试自己的标量乘加）
```

有损解码结果**不**与原始正弦信号比较；参照始终作用在独立解码出来的
压缩域 PCM 上，因此有损编码引入的失真不影响对比。两侧的 decoder 在
整组测试中各自复用，绝不按包重建。

## 矩阵布局

交给 `opus_projection_decoder_create` 的矩阵是
`(streams + coupled_streams) * channels` 个小端 int16，即
**列优先（column-major）**：元素 `(row, col)`（row = 输出声道，
col = 压缩域输入声道）存放在 int16 下标 `col * channels + row`。
系数为有符号 Q15（实际值 = int16 / 32768）。

测试不使用 projection encoder 导出的矩阵，而是自己写一份 4×4
非对称有符号 Q15 矩阵，并自检以下性质（违反视为测试设计错误，
退出码 2）：

- 每行同时含有正系数、负系数和非整数比例（非 0/±1）系数；
- 至少一行合并全部四个输入声道（本矩阵四行皆如此）；
- 每行绝对系数和 ≤ 1.0（Q15 和 ≤ 32768），避免解混削波；
- 矩阵非对称，使行列转置可被观测。

## 独立参照

解混参照是测试自己的标量乘加，作用在独立 multistream decoder 的
输出上。它不调用 `mapping_matrix_*` 系列函数、不包含其内部头文件，
也不是生产实现的副本（生产实现按输入声道累加进输出缓冲，参照按
输出声道做点积，结构不同）。

- **float 入口**：参照用 double 累加
  `sum_c (m[row][c] / 32768) * in[c]`，逐帧逐声道对比，误差上限
  2e-6。同时检查输出样本均为有限数，并检查输出缓冲区前后的哨兵
  未被踩踏。
- **int16 入口**：使用另一组各自独立、初态相同的 decoder 重放同一
  调度。参照按既有规则计算：每个输入的贡献先作 Q15 舍入再相加，
  容差 0（不超过一个量化单位）。

## 舍入

int16 参照的单个贡献按 `floor((m * x + 16384) / 32768)` 计算，与
生产代码的 `(tmp + 16384) >> 15`（算术右移）等价。测试不依赖编译器
对负数右移的习惯，而是用 C99 明确定义的整数运算表达：截断除法加
余数修正（`q = t / 32768; r = t % 32768; if (r < 0) q -= 1;`），
对负数同样得到精确的 floor 结果。

为了证明信号与系数确实能区分"先求总和再舍入"与"逐项舍入再相加"
两种做法，测试同时用两种规则计算参照并统计不同的样本数
（`discriminating`），要求大于 0，否则视为测试设计失败。

## PLC 与 gain、reset 的时序

14 包连续序列中的事件安排：

| 包序号 | 事件 |
| ------ | ---- |
| 0–3    | 正常解码 |
| 4      | 单包丢失：两侧均以 `NULL, len=0` 请求 960 帧 PLC |
| 5–6    | 正常解码（恢复包接续原历史） |
| 7–8    | 两包连续丢失：两侧各请求两次 960 帧 PLC |
| 9      | 正常解码 |
| 10     | 解码前在两侧设置相同解码 gain（-3 dB，Q7.8 即 -768），并核对本次及后续输出 |
| 11–13  | 带 gain 正常解码 |

gain 在每个流解码器内部作用于压缩域 PCM，两侧一致，因此参照无需
对 gain 建模。整组结束后对 projection decoder 执行
`OPUS_RESET_STATE`，再与一个全新初始化、设置了同样 gain 的
projection decoder 重放同一段压缩包（含相同的丢包调度）：

- reset 后的输出必须与全新 decoder 逐样本完全一致；
- reset 后的输出必须仍等于"自备矩阵 × 独立解码 PCM"的参照
  （误差 ≤ 2e-6），即 reset 不能把解混矩阵变成单位阵；另统计与
  恒等解混明显不同的样本数（`nonidentity`），要求大于 0。

每次解码调用前，输出缓冲区先写入非零污染值，防止"只在第一次
调用时清零"的实现蒙混过关。

## 脚本与变异检测

`verification/check_projection_pcm.sh` 先对正常源码构建并运行测试
（输出 `NORMAL_PROJECTION_PCM_PASS`，并打印各组实际比较的样本数，
均须大于 0），再在三个隔离的临时副本里各注入一处缺陷：

- `DETECTED_SIGN`：矩阵载入时忽略负系数的符号（取绝对值）；
- `DETECTED_TRANSPOSE`：float 解混的行列访问转置；
- `DETECTED_CLEAR`：取消 float 输出回调的逐调用清零。

改动只出现在副本中。每个副本必须成功编译并运行同一份测试；只有
对应的数值断言（float 组的 `MISMATCH`，退出码 1）导致非零退出才
计为发现回归。编译失败、崩溃、缺文件或零用例都会使脚本以错误
终止，而不计为发现。
